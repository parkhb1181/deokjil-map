# 프론트엔드 작업 현황

1차 MVP 화면 작업 기록. 다른 컴퓨터에서 이어받을 때 이 문서부터 읽는다.

## 옮겨서 시작하기

```bash
git clone https://github.com/potenup-final/duckmoim-frontend.git
cd duckmoim-frontend
npm install                     # 커밋 훅이 여기서 켜진다
git config core.hooksPath       # .githooks 가 나와야 한다
cp .env.example .env.local
npm run dev                     # localhost:3000
```

**작업물은 전부 팀 저장소(`potenup-final/duckmoim-frontend`)의 `main` 에 있다.**
개인 저장소(`parkhb1181/deokjil-map`)는 8월 30일 소개 페이지에서 멈춰 있다.

`.env.local` 의 카카오 키가 없어도 된다. 지도가 자리표시자로 바뀔 뿐
나머지는 그대로 돈다.

## 명세에서 뺀 것

팀에 공유가 필요한 항목이다. 필수 요구사항이 여럿 빠졌다.

| 명세 | 결정 | 딸려 나온 것 |
|---|---|---|
| AP 전체 (신청·수락) | **뺀다.** 방장이 완료를 누르는 당근 방식 | 모집글 상태가 4개 → 2개, 신청 상태 7개 → 0개. 시간 겹침 검증(AP-07) 불가 |
| PO-04 참여 조건 (성별·연령) | **없는 것으로 한다** | AP-05 조건 검증도 같이 빠짐. 조건이 필요하면 본문에 적는다. 가입 때 **성별도 받지 않는다** |
| PO-11 본문 공개 범위 | **없는 것으로 한다** | 본문은 누구에게나 전체 공개. 상세가 한 화면으로 합쳐짐. 연락은 비밀 댓글로 주고받는다 |
| Q-03 좌표 입력 | **지도에 핀을 찍는다** | 글로도 적고 핀도 찍는다. 핀은 선택이라 안 찍으면 서버가 글을 지오코딩한다 |
| SF 유저 차단 | **뺀다** | 차단 목록 화면(`/me/blocked`)과 프로필의 차단이 같이 빠졌다. 신고는 남는다 |
| CM 답글 (대댓글) | **뺀다** | 댓글이 평평해진다. `parent_id` 가 사라지고 비밀 댓글 권한이 넷에서 셋으로 준다. 「댓글 응답률」 지표도 같이 빠졌다 — 어떤 댓글이 어떤 댓글에 대한 답인지 이을 수 없어 셀 방법이 없다 |
| AD-03 자동 제재 | **뺀다** | 욕설 필터를 두지 않고 운영자가 손으로 처리한다. 백오피스의 「자동 제한 발동」 표시와 그 건을 위로 올리던 정렬도 같이 빠졌다 |
| AU-05 프로필 기록 | **화면에서만 뺀다** | 동행 횟수·완료율·댓글 응답이 사라진다. **도메인 모델에는 남긴다** (`done_count`). 연령대도 넣지 않는다. 미성년 차단에만 쓰는 값이라 남에게 보일 이유가 없다 |
| CM 답글 뎁스 | **1단계 고정** | 회의에서 무제한 얘기가 나왔지만 1차는 1단계다. 무제한이면 비밀 댓글 권한이 재귀가 되어 「부모 댓글 작성자」가 조상 전체인지 직계 부모만인지를 먼저 정해야 한다 |
| PO 필수 입력값 | **셋으로** | 제목·언제·어디서만 필수. 내용과 인원은 선택으로 내렸다. 필수를 늘릴수록 쓰다 마는 사람이 늘어난다. 인원이 선택이 되면서 정원 개념이 흐려지는데, 원래도 표시용이고 자동 마감이 없어 타입은 그대로다 |
| PO 이미지 업로드 | **안 넣는다** | 고른 행사의 포스터만 보여준다. 원본 서버 주소만 들고 있어 CLAUDE.md 의 포스터 재게시 금지와 부딪히지 않는다. 프로필 사진 업로드는 별개로 남아 있어 이미지 스토리지 자체는 필요하다 |
| AD-01 이벤트 수기 등록 | **뺀다** | 백오피스에 등록 폼이 없다. 할 일이 신고뿐이라 탭도 없앴다. 크롤러가 못 가져오는 행사는 모집글에서 행사를 안 고르고 올리면 된다 (`event_id` 가 null 이어도 화면이 다 그려진다) |
| PO 인원 상한 | **6명** | 그 위로는 동행이 아니라 모임이라 알아서 굴러가지 않는다 |
| Q-04 비로그인 목록 노출 | **노출한다** | 로그인 게이트가 화면이 아니라 행동에 붙는다 |
| Q-02 신청자 성별·연령 | **안 보여준다** | 신청 자체가 없어 무의미해짐 |
| PO 모집 마감 입력 | **안 받는다** | 마감은 만나는 날이다. 비우면 만나는 날까지였으니 기본값이 곧 정답인 칸이었다. 서버가 `closes_at` 을 `meet_at` 으로 채운다 |
| 만나는 날 · 시각 | **한 칸으로** | 둘 다 필수였고 서버에서 `meet_at` 하나로 붙는다. 칸만 둘이었지 묻는 것은 하나였다 |
| 프로필 수정 화면 | **1차에 없다** | 화면 목록 12개에 없다. 내 프로필의 액션은 갈 곳 없는 '프로필 수정' 대신 **'내 활동'** 으로 보낸다. 닉네임을 고치는 자리는 `/welcome` 뿐인데 그건 최초 1회용이라 재사용하지 않았다 |

**되돌린 것 — 댓글 신고는 1차에 넣는다.** 회의에서 뺐는데, 신청·수락을
빼기로 하면서 사람 구하는 일이 전부 댓글에서 일어나고 연락처도 비밀
댓글로 오간다. 문제가 생기는 자리가 댓글인데 거기에만 신고가 없으면
글쓴이를 대신 신고하는 우회로밖에 없다.

비용도 거의 없었다. `ReportSheet` 가 처음부터 유저·모집글·댓글 셋을
받게 되어 있고 백오피스의 `Report.target` 에도 `'댓글'` 이 이미 있어서,
부르는 쪽에서 `target` 을 넘기는 한 줄이 전부였다. 그게 빠져 있던 탓에
**댓글의 신고를 눌러도 모집글 신고 시트가 뜨는 버그**로 나타나 있었다.

**성별은 아예 받지 않기로 했다.** 조건이 사라져 성별로 거를 일이
없어졌다. 남은 이유는 미성년 차단(Q-05) 하나인데 그건 연령만으로 된다.
쓰지도 않을 것을 받아두면 유출됐을 때 잃을 것만 늘어난다.

## 정한 것

### 모집글 쓰기에서 묻는 것

여섯이다. **행사(선택) · 제목 · 내용 · 언제 · 어디서 · 몇 명.**

한때 일곱 칸이었다. 시각이 날짜와 따로 있었고 모집 마감이 있었다.
시각은 둘 다 필수인데다 서버에서 `meet_at` 하나로 붙어서, 칸만 둘이었지
묻는 것은 하나였다. 마감은 비우면 만나는 날까지였으니 기본값이 곧
정답인 칸이었다. 아예 없애고 서버가 `closes_at` 을 `meet_at` 으로 채운다.

**행사는 셀렉트가 아니라 접히는 검색 목록이다.** 204건은 스크롤로 훑을
양이 아니고 OS 기본 셀렉트에는 검색이 없다. 닫혀 있으면 한 줄이라 쓰기
화면이 짧아지고, 필요한 사람만 연다. 고르지 않아도 올릴 수 있다 —
콘서트처럼 우리 데이터에 없는 행사가 있어서 필수로 두면 그 글을 못 쓴다.

고르기 목록에 넘길 값은 `p/new/page.tsx` 에서 잘라낸다. `events.json` 이
160KB 라 통째로 클라이언트에 실으면 쓰기 화면 하나가 그만큼 무거워진다.
자르는 일은 빌드타임에 한 번만 돈다.

**만날 자리는 글과 핀 둘 다 받는다.** 핀은 "여기 어디쯤" 이고 글은
"성수역 3번 출구" 다. 핀만 있으면 도착해서도 서로 못 찾고, 글만 있으면
처음 가는 동네에서 그게 어디인지 모른다. 핀은 선택이라 안 찍으면
서버가 글을 지오코딩한다.

**인원은 최대 6명이다.** 화면은 칩으로만 고르게 해뒀지만 서버도 같은
상한을 봐야 한다. 화면만 막으면 API 를 직접 부르면 그만이다.

**끝난 행사는 목록에서 뺀다.** 오늘 날짜는 `useEffect` 에서 확정한다.
서버 프리렌더 시점은 빌드 시각이라 그대로 쓰면 배포 다음날부터 끝난
행사가 남는다.

### 목록과 상세의 사진은 사용자가 올린 것이 아니다

글에 이미지 업로드를 받지 않는다. 글을 쓸 때 **우리가 이미 갖고 있는
생카·콘서트 목록에서 고르고**, 화면에 나오는 사진은 그 행사의 대표
사진(`event_image_url`)이다. 우리가 복제해 두지 않고 원본 서버 주소를
그대로 들고 있는다. 포스터는 저작물이다 (CLAUDE.md).

목록 배치는 [docs/design/SCALE.md](design/SCALE.md) 가 기준이다.
당근·오프메이트·팝가를 실측해서 정했고 왜 그렇게 정했는지가 거기 있다.

### 페이지 껍데기

`PageShell` 이 헤더·뒤로가기·본문 폭을 맡는다. 화면마다 각자 만들면
헤더 높이와 좌우 시작선이 조금씩 달라지고, 그 차이가 화면을 오갈 때
덜컹거림으로 보인다.

### 비회원 게이트

비회원도 목록과 상세를 다 본다. **로그인은 화면이 아니라 행동에 붙는다.**
글쓰기·댓글을 누를 때 시트가 뜬다. 댓글 입력 자리에는 아예 로그인
버튼을 놓는다. 눌러야 막히는 것보다 처음부터 보이는 편이 덜 답답하다.

### 비밀 댓글 권한 — 가장 위험한 자리

채팅이 없어 사람 구하는 일이 전부 댓글에서 일어나고 **연락처가 여기로
오간다.** 판정 입력은 셋뿐이다.

```
보는 사람 · 방장 · 댓글 작성자
```

| 보는 사람 | 공개 | 내 비밀 | 남의 비밀 |
|---|---|---|---|
| 비회원 | 보임 | 없음 | 가림 |
| 일반 회원 | 보임 | 보임 | 가림 |
| 방장 | 보임 | 보임 | **보임** |

한때 「부모 댓글 작성자」 줄이 하나 더 있었다. 답글을 1차에서 빼면서
부모라는 것이 없어졌다.

**판정의 주인은 서버다.** 권한이 없으면 응답에서 `body` 를 통째로
빼고 보낸다. 화면이 가리면 응답에 본문이 남아 개발자 도구로 읽히고,
그건 곧 연락처 유출이다.

`asServerWouldSend()` 는 API 가 없는 동안 목데이터를 그 모습으로
만들어주는 임시 함수다. API 가 붙으면 지운다. 화면은 `body` 가 있는지만
보므로 그때 화면 코드는 안 고쳐도 된다.

### 상태는 셋

```
모집중 ──(방장이 누른다)──→ 모집 완료
   └───(시간이 지난다)───→ 종료
```

끝난 까닭이 다르므로 나눈다. 하나로 묶으면 목록에서 "사람을 다 구해서
닫힌 글" 과 "아무도 안 와서 지나간 글" 이 같아 보인다.

**`ended` 는 서버가 판정한다.** 붙은 행사의 종료 시각이 지나면 `ended`
다. 날짜만 있는 행사(생카·팝업)는 그 날 24시가 종료 시각이고, 행사에
안 붙은 글은 만나는 날(`meet_at`)이 기준이다. **화면이 판정하지
않는다.** 기기 시계가 제각각이고, 누가 열어봐야만 상태가 바뀌는 구조가
된다.

둘 다 회색으로 눌러 둔다(`.is-done`). 구분은 배지 글자로만 한다
(`모집 완료` / `종료`). 색을 나누면 목록에 회색 계열이 둘이 되어
오히려 구분이 흐려진다.

판정을 자리마다 적지 않는다. `isClosed(state)` 한 곳을 쓴다. 상태가
하나 더 늘 때 고칠 곳을 반드시 빠뜨린다.

명세의 OPEN·FULL·CLOSED·CANCELED 넷과는 여전히 다르다. 신청·수락이
없어 정원이 차서 자동 마감되는 경로(FULL)가 없다.

### 로그인

소셜만 둔다. 아이디·비밀번호를 받지 않으므로 비밀번호 찾기와 재설정
화면이 통째로 사라진다. 1주짜리 일정에서 그만큼이 크다.

**가입과 로그인을 나누지 않는다.** 최초 로그인이면 서버가 회원을 만들고
가입 정보 미입력 상태로 들여보낸다 (AU-01). 처음 온 사람도 같은 버튼을
누른다.

주소의 `next` 파라미터로 돌아갈 곳을 들고 다닌다. 글을 읽다가 댓글을
누르고 로그인한 사람은 그 글로 돌아가야지 홈으로 떨어지면 다시
찾아가야 한다.

약관 동의를 따로 누르게 하지 않는다. 버튼을 누르는 것이 동의라고
적어두는 방식이라 화면이 하나 준다.

### 가입 정보 입력

`/welcome` 은 소셜 로그인 직후 한 번만 지난다. 회원은 이미 만들어져
있고 이 값들만 비어 있는 상태다. 그래서 "가입" 이 아니라 "환영" 이다.

채우기 전에는 글쓰기와 댓글이 막힌다 (AU-07). **막는 것은 서버
인터셉터다.** 화면에서만 막으면 API 를 직접 부르면 그만이다.

닉네임 중복은 사전 조회만으로 막을 수 없다. 동시에 같은 이름으로
가입하면 둘 다 통과한다. 유니크 제약이 최종 방어선이고 서버가 409 를
준다 (AU-06). 화면은 그 409 를 받아 그 자리에 문구를 띄운다. 이름을
고치면 문구를 지운다. 고쳤는데 빨간 줄이 남아 있으면 무엇이 문제인지
알 수 없다.

**성별은 받지 않는다.** 참여 조건(PO-04)을 없는 것으로 하면서 성별로
거를 일이 사라졌다. 남은 이유는 미성년 차단(Q-05) 하나인데 그건
연령만으로 된다. 쓰지도 않을 것을 받아두면 유출됐을 때 잃을 것만
늘어난다.

그래서 묻는 것이 둘뿐이다. 닉네임과 연령대. 둘 다 필수라 별표를 달지
않는다 (`docs/design/SCALE.md` 의 「폼」).

### 폼

누르기 전에는 빨간 줄을 띄우지 않는다. 아직 다 안 쓴 것을 두고
틀렸다고 하면 쓰는 내내 혼나는 기분이 든다. 제출을 누른 뒤부터 보여주고,
첫 번째 잘못된 칸으로 스크롤한다.

### 글꼴

Pretendard 를 자체 호스팅한다. 당근이 쓰는 것과 같고 SIL Open Font
License 라 재배포가 허용된다. 직접 자르지 않고 **공식 dynamic-subset 92개**를
받아 경로만 바꿨다.

직접 자르면 코드포인트 순서가 되어 한 페이지가 53조각 1.3MB 를
받아간다. 자주 쓰는 한글 음절이 코드포인트 상에서 흩어져 있어서다.
공식 조각은 빈도순이라 같은 페이지가 12조각 308KB 로 끝난다.

폰트를 판올림하려면 `pretendardvariable-dynamic-subset.css` 를 다시
받아 `url()` 을 `/font/pretendard-N.woff2` 로 바꾸면 된다.

### 색

바탕은 흰색이다. 전에는 아주 옅은 웜 핑크를 깔았는데 그 분홍기가
테두리와 눌린 배경까지 타고 들어가 화면 전체가 물들었다. 글을 읽는
화면이 늘면서 눈에 걸렸다. **분홍은 배지·버튼·링크 같은 강조에만 남긴다.**

토큰은 `src/app/globals.css` 맨 위에 있다. 대비율이 주석에 적혀 있으니
`--text-mute` 보다 밝은 회색을 새로 만들지 않는다.

## 개발용으로 넣어둔 것

인증이 없어 화면을 확인할 방법이 없어서 임시로 둔 것들이다.
**인증이 붙으면 지운다.**

- 상세 위쪽 검은 막대 (보는 사람 넷 전환) — `PostDetail.tsx` 의 `ROLES`
- 목록 위쪽 검은 막대 (정상·비었음·실패·기다리는 중)
- 내 활동 위쪽 검은 막대 (정상·비었음)
- 프로필 위쪽 검은 막대 (남·나 전환)
- `public/dev/map-sample.webp` — 지도 캡처. `NODE_ENV=development` 에서만 그린다.
  **크기와 위 여백을 배포에 나가는 `.locmap__canvas` 와 같은 값으로 맞춰 뒀다**
  (200px, 넓은 화면 260px). 전에는 180px 이라 로컬에서 본 배치와 배포될
  배치가 달랐고, 로컬이 유일한 확인 경로라 그 차이를 아무도 못 봤다

**`/admin15616` 은 인증이 붙기 전에 배포하면 안 된다.** 주소 끝의 숫자는
지나가다 열리는 것만 막는다. 링크를 아는 사람은 그대로 들어오고, 숫자를
늘려도 나아지지 않는다. 서버가 누구인지 확인해야 한다 (Q-13).

온보딩 데모용이라 제재할 사람도 신고할 글도 없어서 이 정도로 뒀다.
실서비스에서는 별도 계정과 접근 제한이 필요하다.

## 이벤트 데이터가 오는 길

```
크롤러 ─┐
        ├─→ DB ──(빌드 시작 때 한 번)──→ events.json ──→ 정적 페이지
KOPIS ──┘                                  커밋 안 함
```

**읽기는 ISR 이다.** 빌드 때 굽고 주기적으로 다시 굽는다. 요청마다 DB 를
타지 않으므로 검색으로 들어오는 롱테일 페이지가 항상 빠르다. 이 서비스는
유입이 대부분 롱테일 검색이라 그 자리를 지키는 것이 중요하다.

`events.json` 을 읽는 곳이 앱 안 7곳(사이트맵 · `/e/[id]` · `/a/[subject]` ·
OG 이미지 · 홈 · 쓰기 · 갤러리)과 노드 스크립트 5개(`og-shots` ·
`indexnow` · `geocode` · `validate-events` · `screen-shots`)다. DB 가
원본이 되어도 이 파일을 빌드 산출물로 남기면 전부 그대로 돈다.

**넘길 때 챙길 것 둘.**

1. **배포 훅.** 지금은 `events.json` 커밋이 배포를 트리거한다
   (`.github/workflows/refresh-data.yml`). 크롤러가 DB 에 쓰면 커밋할 것이
   없어져 배포가 안 걸린다. 워크플로에 훅 호출을 넣어야 한다
2. **0건 방어.** 지금은 파일이 없으면 import 가 터져 빌드가 멈춘다. DB
   쿼리는 빈 배열을 얌전히 돌려주므로, 361개가 사라진 채 배포되고 빌드는
   성공으로 보인다. `pull-events.mjs` 가 직전 건수보다 크게 줄면 멈춰야
   한다. `validate-events.mjs` 가 이미 같은 이유로 있다

## 배포 전에 정해야 하는 것

| 항목 | 상태 |
|---|---|
| `/p/[id]` · `/u/[id]` 가 **동적 렌더(ƒ)** | `next build` 로 확인됨. PROGRESS.md 의 "서버리스 함수 0" 원칙과 어긋난다. MVP 화면을 만들 때부터 그랬고 아직 `generateStaticParams` 가 없다 |
| `/admin15616` 접근 제한 방식 (Q-13) | 미결 |
| 동행 화면에서 앱의 나머지로 가는 길 | **미결.** `/p` · `/p/[id]` · `/me` · `/u/[id]` 는 `PageShell` 의 뒤로가기 하나뿐이고 하단 탭이 없다. 하단 탭은 `/` 안에만 있어서, 공유 링크로 모집글에 들어온 사람은 지도·목록으로 갈 길이 없다. 명세는 내 활동에 홈에서 한 번에 닿으라고 했다(AU-10). 탭을 공용으로 올릴지, 동행을 의도적으로 분리할지 정해야 한다 |

## 백엔드에 넘길 것

`src/types.ts` 의 `CompanionPost` · `PostComment` · `PostAuthor` 가
응답 명세다. 화면이 목데이터를 읽더라도 받는 모양을 먼저 못박아 뒀다.

특히 이 둘을 확인받아야 한다.

- **비밀 댓글은 서버가 `body` 를 빼고 보낸다.** 플래그로 내리고 화면이
  가리는 방식이면 안 된다
- **`meet_lat` · `meet_lng` 는 서버가 채운다.** 사용자는 장소를 글로만
  적는다. 지오코딩 실패면 `null` 이고 지도를 안 그린다

### 공개 프로필에 새로 필요한 값 셋

`/u/[id]` 를 당근 프로필 구조로 다시 잡으면서 생겼다. 셋 다 기존
테이블에서 **세는 값**이라 새 테이블이 없다. 아직 안 오므로 화면은
**값이 있을 때만 그 줄을 그린다** — 없으면 줄이 통째로 빠진다.

| 필드 | 쓰는 자리 | 어떻게 세나 |
|---|---|---|
| `last_seen_at` | 이름 옆 "3일 이내 활동" | 마지막 요청 시각. 알림이 없어서 "내 댓글을 볼 사람인가" 가 여기 걸린다 |
| `posts[].district` | 「쓴 모집글」 행의 메타 줄 | 붙은 행사의 구역. 모집글 자체에는 없어 조인이 필요하다 |
| `posts[].image_url` | 「쓴 모집글」 행 왼쪽 64px 사진 | 붙은 행사의 대표 사진. 같은 글이니 모집글 상세의 `event_image_url` 과 **같은 주소여야 한다**. 우리가 복제해 두지 않는다 (CLAUDE.md) |

**비율은 이 둘 말고 만들지 않는다.** 당근의 재거래희망률(261명 중
255명)에 해당하는 값이 우리에겐 표본 0~3 이라, 비율로 적는 순간
거짓말이 된다. 후기·평점·매너온도는 1차에 두지 않는다.
