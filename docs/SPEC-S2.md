| 대상 스프린트 | S2 (2026-08-31 ~ 2026-09-06) |

## 0. 이번 개정에서 바뀐 것

앞 판과 범위가 크게 다르다. 아래 여섯이 빠지면서 연결된 요구사항과
미결 항목이 함께 사라졌다.

| 빠진 것 | 딸려 나온 것 |
| --- | --- |
| **신청·수락 (AP 16개)** | 모집글 상태 4개 → 3개, 신청 상태 7개 → 0개, 동시성 요구사항 전체, Q-01·Q-02·Q-06·Q-15 |
| **차단 (SF-03·04·06)** | PO-09, CM-13, 열람 권한의 「차단 관계 제외」, 차단 목록 화면 |
| **참여 조건 (PO-04)** | Q-02, 성별 수집 자체 |
| **본문 공개 범위 (PO-11 원안)** | Q-07, 「확정 멤버에게만 공개」 전제 |
| **모집 마감 입력** | PO-02 의 마감시각 검증 절반 |
| **자동 제재 (SF-05)** | AD-02 의 자동 제한 상단 고정, Q-09 |

**연쇄로 사라진 것 하나를 짚어둔다.** 신청·수락이 없으면 확정 멤버가
없고, 확정 멤버가 없으면 「본문을 확정 멤버에게만 공개」 라는 장치가
성립하지 않는다. 그래서 **모집글 본문은 누구에게나 전체 공개다.**
연락 수단은 본문이 아니라 **비밀 댓글**로만 오간다.

## 1. 배경과 이번 범위

브릿지 서비스가 배포되어 사용자를 받고 있다. 생카·팝업 목록은 크롤러가
모은 데이터를 빌드타임 JSON 으로 굽는 형태이며 서버가 관여하지 않는다.
현재 정적 페이지 361개가 검색 유입을 받고 있다.

1차 MVP 는 이 상태 위에 **회원 · 동행 모집글 · 댓글**을 올린다.
신규 개발과 기존 화면 전환이 동시에 일어나며, **전환 실패 시 사용자에게
보이는 목록이 사라지는 위험**이 있다. 이 문서는 그 위험을 명시적으로
다룬다 (5-2, 7).

### 포함 범위

| 도메인 | 포함 근거 |
| --- | --- |
| 회원 | 댓글 작성자 식별과 신고 처리의 전제 |
| 행사 정보 | JSON 을 DB 로 이관. **읽기는 정적을 유지한다** |
| 모집글 | 서비스 진입점 |
| 댓글 (비밀 댓글 포함) | 기술 난이도의 중심. **연락 수단을 전달하는 유일한 경로** |
| 신고 | 낯선 사람 대면 매칭의 최소 안전장치 |
| 백오피스 | 신고 처리 창구 |

### 제외 범위와 대체 수단

| 제외 | 대체 | 재검토 |
| --- | --- | --- |
| 신청·수락 | 댓글로 연락하고 방장이 「모집 완료」 를 누른다 (당근 방식) | S3 |
| 차단 | 신고 | S3 |
| 알림 | 내 활동 내역 화면 | S3 |
| 채팅 | 비밀 댓글 | S3 |
| 참여 조건 (성별·연령) | 필요하면 본문에 적는다 | S3 |
| 자동 제재 (욕설 필터) | 운영자 수동 제재 | S3 |
| 백오피스 이벤트 등록 | 행사를 안 고르고 모집글을 올릴 수 있다 | S3 |
| 콘서트 자동 수집 | 사용자가 제목에 적는다. KOPIS 오픈API 는 S3 | S3 |
| 조회수 | 미노출 | S3 |
| 즐겨찾기 서버 저장 | localStorage. 기기에만 남는다 | S3 |

## 2. 용어 정의

> **정본은 도메인 모델링 문서 1장(유비쿼터스 언어)이다.**
> 여기에는 화면 문구와 직결되는 것만 옮겨 적는다. 어긋나면 도메인
> 문서가 이긴다. 같은 표를 두 곳에 온전히 두면 반드시 갈라진다.

| 화면에 나오는 말 | 식별자 | 이 명세에서 짚을 것 |
| --- | --- | --- |
| 행사 | `Event` | 생카 · 팝업 · **콘서트** 셋 |
| 모집글 | `CompanionPost` | 서비스 진입점 |
| 방장 | `host` | 모집글 작성자 |
| 인원 | `capacity` | **2~6.** 화면 라벨은 「인원」이다 |
| 만나는 시간 | `meetAt` | |
| 만나는 곳 | `MeetPoint` | 글로 적은 장소 + 지도 핀 좌표 |
| 댓글 · 답글 | `Comment` | 답글은 `parentId` 가 있는 것. **깊이 1단계** |
| 비밀 댓글 | `secret` | **연락 수단을 전달하는 유일한 경로** |
| 즐겨찾기 | `Bookmark` | 1차는 기기 저장 |

**화면 라벨과 식별자가 다른 곳이 둘 있다.** 「인원」은 `capacity` 고
「만나는 곳」은 `MeetPoint` 다. 도메인 문서의 한국어(정원 · 만남장소)는
문서용이고 화면에는 쓰지 않는다. 사용자에게 「정원」은 딱딱하다.

**1차에 안 쓰는 용어** `Region` · `ToS` · `AuditLog` · `AdminAccount` 는
도메인 문서에만 있고 이 명세의 화면에는 나오지 않는다.

## 3. 사용자 역할

와이어프레임의 「보는 사람」 토글이 그대로 권한 판정 대상이다.

「댓글 작성자」와 「방장」은 계정 등급이 아니다. **관계 기반 자격**이다.
같은 사람이 A 글에서는 방장이고 B 글에서는 일반 회원이다.

### 열람 권한

| 역할 | 행사 목록·상세 | 모집글 목록·상세 (본문 포함) | 공개 댓글 | 비밀 댓글 |
| --- | --- | --- | --- | --- |
| 비회원 | 가능 | 가능 | 가능 | 전부 자리표시자 |
| 가입 정보 미입력 | 가능 | 가능 | 가능 | 본인 것만 (사실상 없음) |
| 일반 회원 | 가능 | 가능 | 가능 | 본인이 쓴 것만 |
| 댓글 작성자 | 가능 | 가능 | 가능 | 본인 것 + **본인 루트 댓글에 달린 비밀 대댓글** |
| 방장 | 가능 | 가능 | 가능 | 본인 것 + **자기 글의 모든 비밀 댓글·대댓글** |
| 관리자 | 백오피스만 | 백오피스만 | 백오피스만 | 열람 가능. **열람 시 감사 로그 필수** (AD-05) |

**모집글 본문은 비회원에게도 전체 공개다.** 앞 판은 확정 멤버에게만
열기로 했는데 신청·수락이 빠지면서 확정 멤버가 없어졌다. 연락 수단은
본문이 아니라 비밀 댓글로 오간다.

### 작성·관리 권한

| 역할 | 모집글 작성 | 댓글 작성 | 신고 | 삭제 | 상태 변경 |
| --- | --- | --- | --- | --- | --- |
| 비회원 | 불가 | 불가 | 불가 | 불가 | 불가 |
| 가입 정보 미입력 | 403 | 403 | 불가 | 불가 | 불가 |
| 일반 회원 | 가능 | 가능 (OPEN 글에만) | 타인 댓글·글·유저 | 본인 댓글 | 본인 글만 |
| 방장 | 가능 | 가능 | 타인 댓글·글·유저 | 본인 댓글 + **자기 글의 타인 댓글** | **자기 글 완료·취소** |
| 관리자 | 불가 | 불가 | 불가 | 댓글 블라인드 (AD-07) | 유저 제재·해제 |

## 4. 상태 정의

> **전이 규칙의 정본은 도메인 모델링 문서 6장(라이프사이클)이다.**
> 여기에는 **화면이 무엇을 그리는지**만 적는다. 배지 글자와 화면
> 동작은 도메인 문서에 없는 정보라 이 명세가 정본이다.

### 모집글 (`CompanionPost`)

```
        ┌──방장 모집 완료──► CLOSED  (closedReason = MANUAL)
OPEN ───┼──마감시각 경과───► CLOSED  (closedReason = DEADLINE, 배치)
        └──방장 취소───────► CANCELED (사유 필수)
```

| 상태 | 댓글 작성 | 열람 | 수정 | **화면 배지** |
| --- | --- | --- | --- | --- |
| `OPEN` | 가능 | 가능 | 가능 | 모집중 |
| `CLOSED` + `MANUAL` | 409 | 가능 | 불가 | **모집 완료** |
| `CLOSED` + `DEADLINE` | 409 | 가능 | 불가 | **종료** |
| `CANCELED` | 409 | 가능 | 불가 | **취소됨** |

**배지 글자는 셋인데 색은 하나다.** 끝난 셋 모두 회색이다. 「더 못
들어간다」 는 사실이 같고 글자가 이미 다르다. 색까지 나누면 목록에
회색 계열이 셋이 되어 오히려 구분이 흐려진다.

**끝난 까닭을 상태가 아니라 `closedReason` 으로 나눈다.** 상태는
「무엇을 할 수 있나」 를 정하고 까닭은 「왜 그렇게 됐나」 를 말한다.
둘을 상태 하나에 섞으면 닫히는 경로가 늘 때마다 상태가 하나씩 는다.

**`DEADLINE` 판정은 서버가 한다.** 화면이 판정하면 기기 시계에
좌우되고, 누가 열어봐야만 상태가 바뀌는 구조가 된다.

**`FULL` 은 없다.** 확정 인원을 세는 주체가 없다.

### 댓글 (`Comment`)

```
ACTIVE ──작성자·방장 삭제──► DELETED
   └────관리자 블라인드────► BLINDED
```

`DELETED`·`BLINDED` 는 하위 답글이 있으면 「삭제된 댓글입니다」
자리표시자로 남고, 없으면 목록에서 제외된다 (CM-11).

### 회원 (`User`)

가입 축과 제재 축이 독립이다. 자세한 것은 도메인 문서 6장.

```
[가입]  PENDING_SIGNUP_INFO ──입력──► ACTIVE ──탈퇴──► WITHDRAWN
[제재]  NONE ──실행──► WARNED / SUSPENDED / BANNED ──기간 만료──► NONE
```

**화면이 그리는 것**

| 제재 상태 | 화면 |
| --- | --- |
| `NONE` | 아무것도 안 그린다 |
| `WARNED` | 배너 한 줄. **막지 않는다** |
| `SUSPENDED` | 화면을 통째로. 사유 · 해제일 · 이의 경로 |
| `BANNED` | 같음. 해제일 대신 다시 못 쓴다고 적는다 |

## 5. 기능 요구사항

**필수** 9/4 배포 포함 · **권장** 9/6까지 · **선택** 밀리면 S3

### 5-1. 회원 (AU)

| ID | 요구사항 | 우선 | 상세 | 검증 기준 |
| --- | --- | --- | --- | --- |
| AU-01 | 소셜 로그인 | 필수 | 카카오만. 최초 로그인 시 자동 가입, 가입 정보 미입력 상태로 진입 | 인가코드로 자체 토큰 발급까지 성공 |
| AU-02 | 토큰 발급 | 필수 | Access 30분 / Refresh 14일. Refresh 는 서버 저장 | 만료된 Access 로 요청 시 401 |
| AU-03 | 토큰 재발급 | 필수 | Refresh Rotation. 사용된 Refresh 재사용 시 해당 유저 전체 폐기 | 동일 Refresh 2회 사용 시 두 번째 거부 + 기존 세션 무효화 |
| AU-04 | 로그아웃 | 필수 | Refresh 삭제 + Access 잔여 TTL 차단 | 로그아웃 직후 기존 Access 로 401 |
| AU-05 | 가입 정보 입력 | 필수 | **닉네임 · 연령대.** 성별은 받지 않는다 | 저장 후 재조회 시 동일 값 |
| AU-06 | 닉네임 중복 방지 | 필수 | 사전 조회 + DB 유니크 제약 이중 방어 | 동시 요청 2건 중 1건만 성공, 나머지 409 |
| AU-07 | 미입력 유저 차단 | 필수 | **모집글·댓글 작성** API 차단. 조회는 허용 | 미입력 상태로 댓글 작성 시 403, 행사 조회는 200 |
| AU-08 | 프로필 수정 | 권장 | 닉네임 · 한줄소개 · 이미지. **연령대는 잠긴다** | 수정 후 공개 프로필 반영 |
| AU-09 | 공개 프로필 조회 | 필수 | 닉네임 · 프로필 이미지 · 한줄소개 · 쓴 모집글. **연령대·동행 횟수는 노출하지 않는다** | 결정된 노출 범위대로 동작 |
| AU-10 | 내 활동 내역 | 필수 | 내 모집글 / 내 댓글 두 탭 | 비밀 댓글 포함 조회 |
| AU-11 | 회원 탈퇴 | 선택 | 소프트 삭제 + 닉네임 익명화. 작성 댓글은 자리표시자 유지 | 탈퇴 후 댓글 자리표시자 전환 |
| AU-12 | **제재 안내** | 필수 | 정지·영구는 안내 화면만. 경고는 배너. **사유를 본인에게 보여준다** | 정지 유저 로그인 시 안내와 사유 노출 |

#### AU-05 성별을 받지 않는다

참여 조건(PO-04)을 없애면서 성별로 거를 일이 사라졌다. 남은 이유는
미성년 차단(Q-05) 하나인데 그건 연령만으로 된다. **쓰지도 않을 것을
받아두면 유출됐을 때 잃을 것만 늘어난다.**

#### AU-06 이중 방어

사전 조회만으로는 동시 가입 시 중복이 난다. 유니크 제약을 최종
방어선으로 두고 위반 예외를 409로 변환한다.

#### AU-07 차단 지점은 서버다

화면 차단은 API 직접 호출로 우회된다. 서버 인터셉터에서 일괄
처리한다. 대상은 모집글 작성과 댓글 작성 둘이다.

#### AU-09 프로필을 축소했다

동행 횟수·완료율·댓글 응답률을 화면에서 뺐다. **도메인 모델에는
`doneCount` 를 남긴다.** 표본이 0~3인 숫자를 신뢰 신호로 쓰면 처음
온 사람에게 「완료율 0%」 가 낙인이 된다. 연령대는 미성년 차단에만
쓰는 값이라 남에게 보일 이유가 없다.

#### AU-10 알림이 없는 서비스의 유일한 확인 경로

**사용자가 상태를 확인할 수 있는 자리가 여기뿐이다.** 우선순위가
높다. 화면 진입 시마다 재조회하며 폴링은 하지 않는다.

#### AU-12 제재를 주기만 하고 알려주지 않으면 안 된다

백오피스가 제재 사유를 「본인에게 보이는 문구」 로 받는다. 보여줄
화면이 없으면 무엇을 잘못했는지 모르고, 그러면 제재가 사람을 고치는
장치가 아니라 그냥 벌이 된다. 이의 제기 경로도 같이 적는다.

- **경고는 막지 않는다.** 배너로만 알린다. 막을 거면 정지를 준다
- **기간 정지·영구 정지는 화면을 통째로 차지한다** (AD-04)

#### EV-06 복합 커서가 필요한 이유

시작일만으로는 동일 날짜 행사에서 커서가 중복되거나 누락된다. 복합
커서로 고유성을 보장하고 `(startsOn, id)` 인덱스를 둔다.

#### EV-08 읽기 전략이 앞 판과 다르다

```
크롤러 ─┐
        ├─→ DB ──(빌드 시작 때 한 번)──→ events.json ──→ 정적 페이지 361개
KOPIS ──┘                                커밋하지 않음
```

**요청마다 DB 를 타지 않는다.** 갱신은 ISR 로 한다. 이 서비스는 유입
대부분이 롱테일 검색이라, 상세 페이지를 동적으로 바꾸면 검색으로
들어온 사람마다 DB 왕복과 콜드스타트를 겪는다. 지금 정적 361개가 그
트래픽을 받고 있다.

넘길 때 챙길 것이 둘이다.

1. **배포 훅.** 지금은 `events.json` 커밋이 배포를 트리거한다
   (`.github/workflows/refresh-data.yml`, 매일 04:00 KST). 크롤러가
   DB 에 쓰면 커밋할 것이 없어져 배포가 안 걸린다
2. **0건 방어.** 지금은 파일이 없으면 import 가 터져 빌드가 멈춘다.
   DB 쿼리는 빈 배열을 얌전히 돌려주므로 **361개가 사라진 채 배포되고
   빌드는 성공으로 보인다.** 직전 건수보다 크게 줄면 멈춰야 한다

#### EV-09 전환 이후에는 빌드 실패가 목록 소실이다

현재 화면은 서버 없이 동작한다. 복귀 조건을 수치로 정의한다.

#### EV-10 콘서트는 다른 필드가 필요하다

생카·팝업은 기간(`startsOn` ~ `endsOn`)만 있고 시각이 없다.
**콘서트는 그 시각에 못 가면 끝이라** 운영시간(`openHours`)으로
대신할 수 없다.

콘서트 데이터가 들어올 경로는 1차에 없다. 크롤러 수집원(팝가·오프메이트)이
둘 다 콘서트 사이트가 아니고, 인터파크는 `robots.txt` 가 전면 금지다.
**KOPIS 오픈API 가 답이지만 S3 다.** 1차에는 사용자가 행사를 안 고르고
제목에 적는다.

#### EV-11 즐겨찾기를 서버에 두지 않는다

담기는 마찰이 제일 낮아야 하는 행동인데 그 앞에 가입을 세우면 표본이
줄어든다. 기기에만 남으므로 다른 기기에서는 안 보이고, **그 제약을
화면에 적는다.**

서버로 옮길 때 정할 것이 둘이다. **합치는 규칙**(비회원으로 담은 것과
계정에 있는 것. 합집합이 맞다)과 **순서를 지킬지**(「내 코스」일 때는
동선이라 의미가 있었는데 즐겨찾기에는 순서를 기대하는 사람이 없다).

### 5-3. 모집글 (PO)

| --- | --- | --- | --- | --- |

#### PO-01 필수를 셋으로 줄였다

어디서 언제 만나는지만 있으면 글이 성립한다. **필수를 늘릴수록 쓰다
마는 사람이 늘어난다.** 정원이 선택이 되면서 정원 개념이 흐려지는데,
원래도 표시용이고 자동 마감이 없어 타입은 그대로다.

**행사는 선택이다.** 콘서트처럼 우리 데이터에 없는 행사가 있어서
필수로 두면 그 글을 못 쓴다. 행사를 고르면 대표 사진과 이름이 글에
**스냅샷으로 복제된다.** 그래서 모집글이 행사 없이도 혼자 완결된다.

#### PO-02 마감시각 입력을 없앴다

비우면 만나는 날까지였으니 기본값이 곧 정답인 칸이었다. **서버가
`closesAt` 을 `meetAt` 으로 채운다.** 따라서 앞 판의
`마감시각 < 만남시각` 은 성립하지 않는다. 등호를 포함해야 한다.

#### PO-03 Q-03 을 지도 핀으로 닫는다

글과 핀을 둘 다 받는다. 글은 「성수역 3번 출구」 고 핀은 「여기
어디쯤」 이다. **핀만 있으면 도착해서도 서로 못 찾고, 글만 있으면
처음 가는 동네에서 그게 어디인지 모른다.** 핀은 선택이라 안 찍으면
서버가 글을 지오코딩한다.

#### PO-11 본문을 가리지 않는다

앞 판은 확정 멤버에게만 열기로 했는데 신청·수락이 빠지면서 확정
멤버가 없어졌다. **연락 수단은 본문이 아니라 비밀 댓글로 오간다.**
본문에 연락처를 적으면 무차별 노출되므로, 쓰기 화면에서 「연락은 비밀
댓글로 받아도 좋아요」 라고 안내한다.

#### PO-13 검색을 브라우저에서 거른다

목록이 이미 다 내려와 있어 타자마다 바로 좁혀진다. **글이 늘어 목록을
나눠 받게 되면 받아온 페이지 안에서만 찾게 되므로 그때 서버로 옮긴다.**

#### CM-04 열람 권한 매트릭스

> **이 표만 도메인 문서와 양쪽에 둔다.** 배포 판정 시나리오의 핵심이라
> 명세를 보는 사람이 문서를 두 개 열어야 하면 그게 빠뜨리는 원인이 된다.
> **어긋나면 도메인 문서 7.1 이 이긴다.**

| 댓글 유형 | 본문 열람 가능 |
| --- | --- |
| 공개 루트 댓글 | **비회원 포함 전원** |
| 공개 대댓글 | **비회원 포함 전원** |
| 비밀 루트 댓글 | 작성자 본인, 방장 |
| 비밀 대댓글 | 작성자 본인, 방장, **부모 댓글 작성자** |
| 삭제·블라인드 | 없음 (자리표시자만) |

부모 댓글이 비밀이든 공개든 비밀 대댓글의 권한은 같다.

**판정 입력은 ID 네 개뿐이다.**

```
(요청자, 방장, 댓글 작성자, 부모 댓글 작성자)
```

요청자가 `null`(비회원)이면 모든 비밀 댓글이 자리표시자가 된다.
차단이 빠지면서 다섯 번째 입력이 사라졌다.

#### CM-19 문구가 매트릭스와 어긋나면 안 된다

「비밀 댓글은 방장과 쓴 사람만 볼 수 있어요. 답글이면 그 댓글을 쓴
사람도 봅니다」

**문구와 규칙이 어긋나면 연락처를 누가 보는지 모르는 채로 적게 된다.**
규칙을 고칠 때 문구도 같이 고친다.

#### CM-12 댓글 수를 어디에도 저장하지 않는다

저장된 숫자가 없으면 실제와 어긋날 수 없고, 댓글을 쓸 때 모집글 행을
갱신하지 않으므로 동시에 몇 건이 들어와도 서로 기다리지 않는다.

**응답에는 `commentCount` 가 있어야 목록이 그려진다. 컬럼이 아니라
계산값이다.**

#### 마감 순간의 댓글 1건은 허용한다

열린 글인지 확인하는 검사는 트랜잭션 밖의 읽기다. 방장이 마감하는
순간 진행 중이던 작성 한 건이 닫힌 글에 들어올 수 있다. 닫힌 글도
열람은 되고 사용자가 잃는 것이 없어 막지 않는다.

### 5-5. 신고 (SF)

#### 신고 시트는 하나다

`ReportSheet` 하나가 유저·모집글·댓글 셋을 맡는다. 부르는 쪽이

#### 차단을 뺀 이유와 되살릴 시점

지금은 댓글뿐이고 공개 글에 달리며 방장이 다 본다. 불편하면 신고하면
된다.

**S3 에서 채팅이 들어오면 차단을 같이 넣어야 한다.** 남이 나에게 직접
말을 걸 수 있게 되는 순간 신고만으로는 부족하다. 신고는 처리에 시간이
걸리는데 그 사이에도 메시지는 온다.

**PC 화면이다.** 나머지는 휴대폰으로 쓰는 서비스지만 이건 운영자가

#### AD-06 은 아직 안 붙었다

지금은 주소 끝에 숫자를 붙여둔 것이 전부다. **보안이 아니라 자물쇠
그림이다.** 링크를 아는 사람은 그대로 들어온다. 실서비스 배포 전에
서버가 누구인지 확인해야 한다.

#### NF-04 모집글에 이미지 업로드를 받지 않는다

목록과 상세에 나오는 사진은 **고른 행사의 대표 사진**이고, 우리가
복제하지 않고 원본 서버 주소를 그대로 들고 있다. 사용자가 포스터를
올리면 그건 우리가 복제하는 것이 된다. 프로필 사진은 별개라 스토리지
자체는 필요하다.

#### NF-11 · NF-12 주소가 바뀌면 색인이 날아간다

지금 행사 주소가 외부 식별자다(`/e/pg_8417`). PK 를 URL 에 쓰면 정적
214개와 사이트맵 273개가 전부 바뀌고, **롱테일 검색 색인을 처음부터
다시 쌓아야 한다.** 회복에 몇 주 걸린다.

`CompanionPost.eventId` 가 PK 인지 외부 식별자인지 정해야 한다.
프론트가 그 값으로 `/e/{값}` 링크를 만든다. PK 라면 `eventSlug` 를
따로 줘야 한다 (Q-16).

## 7. 배포 판정 기준

아래 주 시나리오가 운영 환경에서 끊김 없이 완주하면 9/4 배포 성공으로
판정한다. **신청·수락이 빠지면서 시나리오가 짧아졌다.**

```
소셜 로그인
  → 가입 정보 입력 (닉네임 · 연령대)
  → 행사 목록 조회 (마이그레이션 데이터)
  → 행사 상세 진입
  → 모집글 작성 (제목 · 만남시각 · 만남지점)
  → (다른 계정) 비밀 댓글로 연락처 남김
  → (방장) 비밀 댓글 본문 확인
  → (제3의 계정) 같은 댓글이 자리표시자로만 보이는지 확인
  → (방장) 모집 완료
  → 내 활동 내역에서 확인
```

**「제3의 계정에게 자리표시자로 보이는지」 가 이 시나리오의 핵심이다.**
거기서 본문이 새면 연락처가 새는 것이고, 그게 1차에서 가장 큰 사고다.

**보조 시나리오, 9/6까지**

- 신고 접수 → 백오피스 큐 노출 → 제재 실행 → **제재당한 계정에 사유가 보임**
- 백오피스 신고 처리 → 감사 로그 기록
- 마감 배치 → `CLOSED(DEADLINE)` 전이 → 배지가 「종료」 로

**전환 안정성 기준**

- 행사 목록 조회 실패율이 임계치를 5분 이상 초과하면 이전 빌드로 복귀
- 복귀 절차는 배포 전 1회 리허설 완료
- **빌드 시 행사 건수가 직전보다 크게 줄면 배포를 멈춘다** (EV-08)

**기본값** 열은 결정이 미뤄질 때 개발자가 임의 판단하지 않도록 정해둔

### 10-1. 착수 전 결정

| ID | 주제 | 쟁점 | 선택지 | 기본값 |
| --- | --- | --- | --- | --- |
| Q-05 | 미성년자 가입 허용 | 낯선 성인과의 대면 매칭이다. 연령대 입력만 받고 검증은 없다 | ① 연령대 선택지에서 미성년 제외 ② 허용 ③ 미성년끼리만 | ① 미성년 제외 |
| Q-13 | 관리자 인증 방식 | 지금은 주소 난독화가 전부다 | 환경변수 단일 계정 / IP 제한 / 별도 로그인 | 환경변수 단일 계정 + IP 제한 |
| Q-16 | **`eventId` 가 PK 인가 외부 식별자인가** | 프론트가 그 값으로 `/e/{값}` 링크를 만든다 | ① 외부 식별자를 담는다 ② PK + `eventSlug` 별도 | ① 외부 식별자 |

**Q-17(API 필드 표기)은 닫혔다. 전부 camelCase 다.** 동행
쪽(`CompanionPost` · `Comment` · `User` · `Sanction`)과 `EventItem` 이
같은 표기를 쓴다. 프론트 타입 · 목데이터 · `events.json` 214건 ·
크롤러 출력부를 **한 커밋에서 같이** 바꿨다.

크롤러를 같이 바꾼 이유는, 프론트만 바꾸면 `events.json` 이 여전히
`starts_on` 을 주므로 값이 전부 `undefined` 가 되기 때문이다.
**화면이 깨지지도 않고 조용히 빈칸이 되는 쪽이라 더 나쁘다.** 다음
수집이 도는 새벽 4시에 되살아나는 종류의 사고다.

**DB 컬럼은 snake_case 그대로다.** `bridge-plan-full.md` 7번의 DDL 은
Postgres 관례를 따르고, camelCase 는 **API 응답의 표기**다. 둘 사이
매핑은 서버가 한 곳에서 처리한다. 경계는 「저장하는 이름」 대
「주고받는 이름」 이다.

**Q-04(관리자의 비밀 댓글 열람)는 닫혔다.** 도메인 문서 7.1 이
「관리자 열람 가능」 으로 확정했다. **열람을 허용하면 감사 로그가
유일한 견제 장치이므로 AD-05 를 권장에서 필수로 올린다.**
