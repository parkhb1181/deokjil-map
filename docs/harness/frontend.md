# 프론트엔드 하네스

팀 하네스 문서의 프론트엔드 절. `youstar-frontend` 저장소 기준.

하네스는 "에이전트에게 잘 부탁하는 법"이 아니다. **사람이 매번 다시 설명하지
않아도 되게 만드는 저장소 설정**이다. 부탁은 지켜지지 않을 수 있고, 설정은
지켜진다. 이 구분이 아래 배치의 전부다.

## 무엇을 어디에 두는가

| 층 | 파일 | 언제 읽히나 | 성격 |
|---|---|---|---|
| 상시 규칙 | `CLAUDE.md` | 세션 시작마다 전부 | **참고**. 안 지켜질 수 있다 |
| 경로별 규칙 | `.claude/rules/*.md` + `paths:` | 해당 파일을 열 때만 | **참고** |
| 절차 | 스킬 | 호출하거나 관련될 때 | **참고** |
| 금지 | `.claude/settings.json` `permissions.deny` | 도구 호출 시점 | **강제**. 못 뚫는다 |
| 시점 고정 | 훅 | 커밋 전 같은 고정 지점 | **강제** |

공식 문서가 명시한다. CLAUDE.md 는 시스템 프롬프트가 아니라 컨텍스트라
준수가 보장되지 않는다. **막아야 하는 것은 규칙이 아니라 설정으로 막는다.**

### CLAUDE.md 는 200줄 아래로

길수록 컨텍스트를 먹고 준수율이 떨어진다. 지금 114줄이라 여유가 있지만,
늘어나면 다음 순서로 뺀다.

1. 한 영역에서만 쓰는 규칙 → `.claude/rules/` 에 `paths:` 를 달아 옮긴다
2. 여러 단계짜리 절차 → 스킬로 옮긴다
3. `@경로` 임포트는 **줄여주지 않는다.** 시작할 때 같이 로드된다. 정리용일 뿐이다

`.claude/rules/` 에서 `paths:` 없는 파일은 시작할 때 다 읽힌다. 경로를
달아야 그 파일을 열 때만 읽힌다.

### AGENTS.md 를 읽지 않는다

Claude Code 는 `CLAUDE.md` 만 읽는다. 그런데 **Next.js 16.3 부터 `next dev` 가
`AGENTS.md` 를 자동 생성하고 갱신한다.** 이 저장소가 16.3.3 이다.

둘을 한 벌로 유지하려면 `CLAUDE.md` 첫 줄에 `@AGENTS.md` 를 넣는다. 윈도우는
심볼릭 링크에 관리자 권한이 필요하니 임포트를 쓴다.

직접 쓸 내용은 `BEGIN:nextjs-agent-rules` 마커 **바깥**에 쓴다. 안은 덮어쓰인다.

## 팀 연동 위에서 지킬 것

Jira, GitHub, Slack 이 이미 물려 있다. **에이전트가 손으로 하면 안 되는 일이
생겼다는 뜻이다.** 손으로 하면 자동화가 만든 것과 어긋난다.

### 브랜치를 만들지 않는다

Jira 티켓을 **진행 중으로 옮기면** 워크플로가 자동으로 만든다.

```
Jira 제목  feat: 소셜 로그인 구현
              ↓  접두사 한 단어가
브랜치     feat/YS-12
라벨       feat
커밋 타입   feat
```

그 한 단어가 셋을 다 결정한다. 워크플로 주석의 표현대로 단일 기준이다.
**Jira 제목을 `타입: 내용` 형식으로 쓰는 것이 사실상의 규약이다.** 접두사가
없으면 이슈 유형으로 떨어지고 경고가 남는다.

브랜치가 안 생겼으면 Jira 자동화 규칙이 이 저장소를 안 가리키는 것이다.
직접 만들어 덮지 말고 규칙을 고친다.

### 커밋 메시지에 `[KEY]` 를 붙이지 않는다

`.githooks/prepare-commit-msg` 가 브랜치명에서 키를 뽑아 붙인다.

```
feat/YS-12  +  "feat: 로그인"   →   [YS-12] feat: 로그인
```

**훅은 클론마다 켜야 한다.** 백엔드는 Gradle 이 켜주고 프론트는 그런 게
없었다. 그래서 `package.json` 에 넣었다.

```json
"prepare": "git config core.hooksPath .githooks || exit 0"
```

`npm install` 하면 켜진다. 안 켜져 있으면 키가 안 붙어 Jira 와 연결이 끊긴다.
확인은 `git config core.hooksPath` 가 `.githooks` 를 뱉는지 보면 된다.

### PR 본문 앞부분을 쓰지 않는다

Jira 정보와 커밋 기반 작업 내역은 PR 을 열면 자동으로 붙는다. 요구사항과
배경은 Jira 에 있으니 옮겨 적지 않는다. 사람이 채우는 칸은 넷이다.

- 🔍 리뷰 포인트
- 🧪 테스트 방법
- 📸 **스크린샷 (UI 변경 시)**
- ✅ 체크리스트

세 번째가 프론트에만 걸린다. 프론트 PR 은 거의 다 UI 변경이라 **사실상 매번
필수**다. 아래 검증 절차가 이걸 위해 있다.

## 화면 바꾸면 눈으로 확인한다

타입체크가 통과했다는 것은 렌더된다는 뜻이 아니다. 화면을 건드렸으면 브라우저로
열어서 확인하고, 그 결과를 PR 스크린샷 칸에 넣는다.

```bash
npm run dev        # localhost:3000, 포트 고정
```

포트가 고정인 이유는 카카오 JS 키 도메인 등록이 **포트까지 일치**해야 하기
때문이다. `predev` 가 3000 점유를 미리 검사한다.

확인 순서. 콘솔 오류 → 화면 구조 → 상호작용 → 반응형. 겪은 것 둘.

- **화면이 숨겨진 상태면 `IntersectionObserver` 가 한 번도 안 불린다.** 뷰포트
  높이가 0 이라 그렇다. 등장 애니메이션을 이걸로 만들면 숨긴 채로 끝난다.
  실패해도 내용은 남게 만들어야 한다
- **런타임 재렌더가 붙여둔 리스너를 떼간다.** 캐시한 엘리먼트를 믿지 말고
  `document` 에 위임하거나 매번 다시 찾는다

## 손대면 안 되는 곳

`.claude/settings.json` 이 막고 있다. 규칙이 아니라 설정이라 안 뚫린다.

| 경로 | 상태 | 이유 |
|---|---|---|
| `.githooks/**` | 금지 | 팀 공용. 백엔드 빌드가 참조한다 |
| `.github/scripts/**` | 금지 | 팀 공용 Jira 연동 |
| `.github/workflows/jira-*.yml` | 금지 | 팀 공용 |
| `.github/PULL_REQUEST_TEMPLATE.md` | 금지 | 팀 공용 |
| `src/data/events.json` | 물어봄 | 봇이 매일 04:00 KST 덮어쓴다 |

`.github/workflows/refresh-data.yml` 은 **우리 것**이라 안 막았다.

프론트 밖 코드를 고쳐야 하면 직접 고치지 않는다. 무엇이 왜 필요한지 적어
담당자에게 넘긴다.

## 새로 들어온 사람

```bash
git clone https://github.com/potenup-final/youstar-frontend.git
cd youstar-frontend
npm install                          # 커밋 훅이 여기서 켜진다
git config core.hooksPath            # .githooks 가 나와야 한다
cp .env.example .env.local           # 키 없으면 지도가 리스트로 폴백한다
npm run dev
```

읽는 순서는 [README](../../README.md) 의 파일 구조, [CLAUDE.md](../../CLAUDE.md)
의 작업 규칙이다. 특히 **출처 표기와 원본 재게시 금지**는 어기면 사용자가
헛걸음하고 지표가 오염된다.

## 백엔드와 맞춰야 하는 것

이 문서는 프론트 절이다. 팀 문서로 합칠 때 아래는 한 벌이어야 한다.

- **Jira 제목 형식.** `타입: 내용`. 접두사가 브랜치와 라벨을 만든다
- **커밋 타입 목록.** 프론트만 `style` 을 더 쓰는 식이면 라벨이 갈린다
- **훅 설치 시점.** 백엔드는 Gradle, 프론트는 `npm install`. 방식은 달라도
  결과는 같아야 한다
- **PR 체크리스트.** 지금 템플릿의 넷은 백엔드 기준이다. 프론트는 스크린샷이
  사실상 필수라는 점만 다르다
