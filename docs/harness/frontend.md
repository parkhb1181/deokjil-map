# 프론트엔드 하네스

팀 하네스 문서의 프론트엔드 절. `youstar-frontend` 저장소 기준.

하네스는 "에이전트에게 잘 부탁하는 법"이 아니다. **사람이 매번 다시 설명하지
않아도 되게 만드는 저장소 설정**이다. 부탁은 지켜지지 않을 수 있고, 설정은
지켜진다. 이 구분이 아래 배치의 전부다.

## 무엇을 어디에 두는가

| 층 | 파일 | 언제 | 세기 |
|---|---|---|---|
| 참고 | `CLAUDE.md` | 세션 시작마다 전부 | 안 지켜질 수 있다 |
| 참고 | 오토 메모리 (`MEMORY.md`) | 세션 시작마다 앞 200줄 | 안 지켜질 수 있다 |
| 참고 | `.claude/rules/*.md` + `paths:` | 해당 파일을 열 때 | 안 지켜질 수 있다 |
| 참고 | 스킬 | 호출하거나 관련될 때 | 안 지켜질 수 있다 |
| 1차 방어 | `permissions.deny` | 도구 호출 시점 | **Edit·Read 만** 본다 |
| 2차 방어 | PreToolUse 훅 | 도구 호출 시점 | 도구 전부. 로컬이라 끌 수 있다 |
| 2차 방어 | git 훅 | 커밋 시점 | 로컬이라 끌 수 있다 |
| **강제** | CODEOWNERS·브랜치 보호·필수 CI | 푸시·머지 시점 | **여기만 진짜 막힌다** |

공식 문서가 명시한다. CLAUDE.md 는 시스템 프롬프트가 아니라 컨텍스트라 준수가
보장되지 않는다. 반면 설정 규칙은 클라이언트가 강제한다. 다만 **강제의 범위가
좁다.** 아래 두 절이 그 범위 이야기다.

### 오토 메모리도 같이 로드된다

에이전트가 스스로 쓴 메모가 `~/.claude/projects/<프로젝트>/memory/` 에 쌓이고
세션마다 같이 읽힌다. 사람이 쓴 게 아니라 **개인 기기에 남는 것**이라 팀원마다
다르다. `CLAUDE.md` 와 어긋나면 저장소 규칙이 이긴다. 이상하게 굴면 `/memory`
로 열어보고 지운다.

### CLAUDE.md 는 200줄 아래로

공식 문서의 권고치다. 길수록 컨텍스트를 먹고 준수율이 떨어진다. 지금 114줄이라
여유가 있다. 늘어나면 다음 순서로 뺀다.

1. 한 영역에서만 쓰는 규칙 → `.claude/rules/` 에 `paths:` 를 달아 옮긴다
2. 여러 단계짜리 절차 → 스킬로 옮긴다
3. `@경로` 임포트는 **줄여주지 않는다.** 시작할 때 같이 로드된다. 정리용일 뿐이다

**옮긴 뒤에 `/context` 로 확인한다.** Memory files 목록에 그 파일이 안 떠야
성공이다. 떠 있으면 `paths:` 가 안 먹은 것이고 토큰은 그대로 나간다. 조용히
실패하므로 확인하지 않으면 모른다. 안 먹으면 하위 디렉터리 `CLAUDE.md` 로
바꾼다. 그건 해당 디렉터리 파일을 읽을 때 로드되는 것이 확인된 동작이다.

`/doctor` 가 체크인된 CLAUDE.md 의 군더더기를 잘라준다. 코드에서 알 수 있는
디렉터리 구조나 의존성 목록을 걷어내고 함정과 근거를 남기는 식이다. 분기마다
한 번 돌릴 만하다.

### AGENTS.md 를 만들지 않는다

`node_modules/next/dist/server/lib/generate-agent-files.js` 를 직접 읽고 확인한
동작이다. 흔한 오해가 있어서 적어둔다.

```
AGENTS.md 있음  →  AGENTS.md 에 블록, CLAUDE.md 는 건드리지 않음
없고 CLAUDE.md 있음  →  CLAUDE.md 에 블록, AGENTS.md 만들지 않음   ← 우리
둘 다 없음  →  AGENTS.md 에 블록, CLAUDE.md 는 "@AGENTS.md" 한 줄
```

**블록은 항상 한 파일에만 산다.** 우리는 `CLAUDE.md` 가 이미 있고 `AGENTS.md`
가 없으므로 **`CLAUDE.md` 가 호스트**다. 지금 106행부터 114행이 그것이다.

따라서 이 저장소에서는,

- `AGENTS.md` 를 만들지 않는다. 만들면 다음 `next dev` 부터 블록이 그쪽으로
  옮겨가고 `CLAUDE.md` 는 갱신이 멈춘다
- `@AGENTS.md` 임포트를 넣지 않는다. 대상 파일이 없다
- 직접 쓸 내용은 `BEGIN:nextjs-agent-rules` 마커 **바깥**에 쓴다. 안은 덮어쓰인다.
  이 규칙이 `AGENTS.md` 가 아니라 **`CLAUDE.md` 에 적용된다**

Claude Code 가 `AGENTS.md` 를 읽지 않는 것은 사실이지만, 우리에게는 애초에
그 파일이 없어야 하므로 문제가 되지 않는다.

참고로 16.3 은 stable 이 16.2.10 에 머문 상태에서 프리뷰로 나간 계열이다.
지금 16.3.3 을 쓰고 있으므로 위 동작은 버전이 바뀌면 다시 확인한다.

## 팀 연동 위에서 지킬 것

Jira, GitHub, Slack 이 이미 물려 있다. **에이전트가 손으로 하면 안 되는 일이
생겼다는 뜻이다.** 손으로 하면 자동화가 만든 것과 어긋난다.

### 브랜치를 만들지 않는다

Jira 티켓을 **진행 중으로 옮기면** 워크플로가 자동으로 만든다.

```
Jira 제목  feat: 소셜 로그인 구현
              ↓  접두사 한 단어가
브랜치     feat/YS-12
라벨       feat
커밋 타입   feat
```

그 한 단어가 셋을 다 결정한다. 워크플로 주석의 표현대로 단일 기준이다.
**Jira 제목을 `타입: 내용` 형식으로 쓰는 것이 사실상의 규약이다.** 접두사가
없으면 이슈 유형으로 떨어지고 경고가 남는다.

브랜치가 안 생겼으면 Jira 자동화 규칙이 이 저장소를 안 가리키는 것이다.
직접 만들어 덮지 말고 규칙을 고친다.

### 커밋 메시지에 `[KEY]` 를 붙이지 않는다

`.githooks/prepare-commit-msg` 가 브랜치명에서 키를 뽑아 붙인다.

```
feat/YS-12  +  "feat: 로그인"   →   [YS-12] feat: 로그인
```

훅 종류를 잘 골랐다. `pre-commit` 과 `commit-msg` 는 `--no-verify` 로 넘어가지만
`prepare-commit-msg` 는 그 옵션의 대상이 아니다.

**그래도 강제가 아니다.** `git -c core.hooksPath=/dev/null commit` 이면 훅을
못 찾아 없는 것처럼 동작한다. 설치도 클론마다 해야 한다. 백엔드는 Gradle 이
켜주고 프론트는 그런 게 없어서 `package.json` 에 넣었다.

```json
"prepare": "git config core.hooksPath .githooks || exit 0"
```

`|| exit 0` 은 git 없는 환경에서 `npm install` 이 깨지지 않게 하려는 것이다.
**대신 실패가 조용히 넘어간다.** 그래서 확인이 사람 몫으로 남는다.

```bash
git config core.hooksPath      # .githooks 가 나와야 한다
```

이 실패 모드를 사람에게 떠넘기지 않으려면 **`[KEY]` 누락을 PR 필수 체크로**
올려야 한다. 커밋 메시지 정규식 검사 워크플로 하나면 된다. 훅은 빠른 피드백,
CI 가 강제. 아직 안 만들었고 아래 "남은 것"에 적어뒀다.

### PR 본문 앞부분을 쓰지 않는다

Jira 정보와 커밋 기반 작업 내역은 PR 을 열면 자동으로 붙는다. 요구사항과
배경은 Jira 에 있으니 옮겨 적지 않는다. 사람이 채우는 칸은 넷이다.

- 🔍 리뷰 포인트
- 🧪 테스트 방법
- 📸 **스크린샷 (UI 변경 시)**
- ✅ 체크리스트

세 번째가 프론트에만 걸린다. 프론트 PR 은 거의 다 UI 변경이라 **사실상 매번
필수**다. 지금은 사람이 기억해야 하는데, 문서 자신의 논리대로면 이것도 체크로
올라가야 한다. `src/app` 이나 `src/components` 에 diff 가 있는데 스크린샷 칸이
비어 있으면 실패시키는 액션. 이것도 "남은 것"에 있다.

## 화면 바꾸면 눈으로 확인한다

타입체크가 통과했다는 것은 렌더된다는 뜻이 아니다.

```bash
npm run dev        # localhost:3000, 포트 고정
```

포트가 고정인 이유는 카카오 JS 키 도메인 등록이 **포트까지 일치**해야 하기
때문이다. `predev` 가 3000 점유를 미리 검사한다.

확인 순서. 콘솔 오류 → 화면 구조 → 상호작용 → 반응형. 겪은 것 둘.

- **화면이 숨겨진 상태면 `IntersectionObserver` 가 한 번도 안 불린다.** 뷰포트
  높이가 0 이라 그렇다. 등장 애니메이션을 이걸로 만들면 숨긴 채로 끝난다.
  실패해도 내용은 남게 만들어야 한다
- **런타임 재렌더가 붙여둔 리스너를 떼간다.** 캐시한 엘리먼트를 믿지 말고
  `document` 에 위임하거나 매번 다시 찾는다

## 손대면 안 되는 곳

| 경로 | 상태 | 이유 |
|---|---|---|
| `.githooks/**` | 금지 | 팀 공용. 백엔드 빌드가 참조한다 |
| `.github/scripts/**` | 금지 | 팀 공용 Jira 연동 |
| `.github/workflows/jira-*.yml` | 금지 | 팀 공용 |
| `.github/PULL_REQUEST_TEMPLATE.md` | 금지 | 팀 공용 |
| `src/data/events.json` | 물어봄 | 봇이 매일 04:00 KST 덮어쓴다 |

`.github/workflows/refresh-data.yml` 은 **우리 것**이라 안 막았다.

### 왜 두 겹인가

`permissions.deny` 의 `Edit(...)` 규칙은 **Edit 도구만 본다.** 공식 문서가
명시한다. `Write(...)`, `NotebookEdit(...)` 로 쓴 경로 규칙은 받아들여지되
참조되지 않고 시작할 때 경고만 뜬다.

문제는 Bash 다. `deny` 를 걸어도 이것들은 다른 도구라 안 걸린다.

```bash
sed -i 's/x/y/' .githooks/prepare-commit-msg
cat > .github/scripts/jira.sh
git checkout main -- .github/workflows/jira-dispatch.yml
```

그래서 `.claude/hooks/guard-shared.mjs` 를 PreToolUse 로 걸어 그 문을 닫았다.
Bash 명령에 보호 경로와 쓰기 표현이 같이 나오면 exit 2 로 막는다. 읽기는
통과시킨다. `cat .githooks/...` 는 되고 `cat > .githooks/...` 는 안 된다.

**이것도 완전하지 않다.** 쓰기를 표현하는 방법은 무한하고 훅에 적힌 패턴은
유한하다. 훅은 로컬이라 끌 수도 있다. **로컬 두 겹은 실수를 잡는 장치이고,
진짜 보장은 원격에 있다.** 어차피 이 파일들은 에이전트만이 아니라 사람도 못
고치게 해야 한다.

- `CODEOWNERS` 로 해당 경로에 백엔드 담당자를 지정
- 브랜치 보호에서 코드오너 승인 필수

둘 다 아직 없다. 저장소 관리자 권한이 필요해서 "남은 것"에 뒀다.

프론트 밖 코드를 고쳐야 하면 직접 고치지 않는다. 무엇이 왜 필요한지 적어
담당자에게 넘긴다.

### `events.json` 은 금지가 아니라 확인

봇이 매일 04:00 KST 에 수집·정규화한 결과로 덮어쓴다. **사람이 손으로 고치면
다음 날 아침에 사라진다.** 급할 때 한 번 고치는 건 되게 두되, 고쳤으면 같은
결과가 나오도록 `crawler/` 쪽을 고쳐야 한다. 대개는 `kpop-artists.json` 에
이름을 추가하는 일이다.

## 새로 들어온 사람

```bash
git clone https://github.com/potenup-final/youstar-frontend.git
cd youstar-frontend
npm install                          # 커밋 훅이 여기서 켜진다
git config core.hooksPath            # .githooks 가 나와야 한다
cp .env.example .env.local           # 키 없으면 지도가 리스트로 폴백한다
npm run dev
```

읽는 순서는 [README](../../README.md) 의 파일 구조, [CLAUDE.md](../../CLAUDE.md)
의 작업 규칙이다. 특히 **출처 표기와 원본 재게시 금지**는 어기면 사용자가
헛걸음하고 지표가 오염된다.

## 백엔드와 맞춰야 하는 것

이 문서는 프론트 절이다. 팀 문서로 합칠 때 아래는 한 벌이어야 한다.

- **강제 계층.** 가장 중요하다. 같은 파일을 프론트는 막고 백엔드는 안 막으면
  막은 쪽만 불편하고 파일은 그대로 바뀐다. `deny` 와 훅 정책을 맞추거나,
  아예 원격 한 곳에서만 막고 로컬은 안내로 통일한다
- **Jira 제목 형식.** `타입: 내용`. 접두사가 브랜치와 라벨을 만든다
- **커밋 타입 목록.** 프론트만 `style` 을 더 쓰는 식이면 라벨이 갈린다
- **훅 설치 시점.** 백엔드는 Gradle, 프론트는 `npm install`. 방식은 달라도
  결과는 같아야 한다
- **PR 체크리스트.** 지금 템플릿의 넷은 백엔드 기준이다. 프론트는 스크린샷이
  사실상 필수라는 점만 다르다

## 남은 것

- [ ] 커밋 메시지 `[KEY]` 검사 워크플로 추가
- [ ] UI diff 가 있는데 스크린샷 칸이 비면 실패시키는 워크플로 추가
- [ ] Jira 자동화 규칙이 이 저장소를 가리키는지 확인. 아직 dispatch 가 한 번도
      안 왔다
