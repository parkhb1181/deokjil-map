# 도메인 문서와 어긋난 곳

| | |
| --- | --- |
| 작성 | 2026-09-01 |
| 대조한 것 | 도메인 모델링 문서 · `docs/SPEC-S2.md` · 실제 프론트 코드 |
| 어긋난 곳 | 다섯 |

문서가 둘이면 같은 사실이 두 곳에 적히고, 한쪽만 고쳐지면 갈라진다.
아래 다섯이 지금 갈라져 있다. **어느 쪽이 맞는지 정해주시면 코드와
명세를 그쪽에 맞추겠습니다.**

읽는 법: 각 항목은 「무슨 일이 벌어지나」 부터 읽으면 된다. 그게
사용자에게 어떻게 보이는지다.

---

## 1. 모집글을 취소할 방법이 없어졌다

### 무슨 일이 벌어지나

방장이 글을 잘못 올렸다. 날짜를 틀렸거나, 사정이 생겨 못 가게 됐다.
**지울 방법도 취소할 방법도 없다.** 「모집 완료」 를 누르면 사람을 다
구한 것처럼 보이고, 그냥 두면 만나는 날까지 모집중으로 남아 누군가
계속 댓글을 단다.

### 어디가 어긋났나

| | 내용 |
| --- | --- |
| 도메인 문서 6장 | `OPEN → CLOSED(MANUAL)` · `CLOSED(DEADLINE)` **둘뿐** |
| 도메인 문서 3.1 | `CompanionPost` 경계 안에 `closedReason` 은 **있다** |
| SPEC-S2 PO-10 | 모집글 취소, 사유 필수, **우선순위 필수** |
| 프론트 코드 | `PostState = 'OPEN' \| 'CLOSED' \| 'CANCELED'` |

앞 판 도메인 문서에는 `CANCELED` 가 있었다. 이번 판에서 상태도에서만
빠졌고 나머지 자리에는 흔적이 남아 있다.

### 제 의견

**되살리는 쪽입니다.** 취소가 없으면 잘못 올린 글을 처리할 길이
없습니다. 「모집 완료」로 대신하면 **사람을 구했다는 거짓 신호**가
목록에 남습니다.

---

## 2. 방장이 자기 글의 댓글을 못 지운다

### 무슨 일이 벌어지나

내 모집글에 광고 댓글이 달렸다. **내가 지울 수 없다.** 할 수 있는
것은 신고뿐인데, 운영자가 처리할 때까지 그 광고가 내 글에 그대로
붙어 있다. 야간이나 주말이면 하루 넘게 남는다.

### 어디가 어긋났나

| | 내용 |
| --- | --- |
| 도메인 문서 6장 (앞 판) | `ACTIVE ──작성자·방장 삭제──► DELETED` |
| 도메인 문서 6장 (이번 판) | `ACTIVE ──작성자 삭제──► DELETED` **방장이 빠졌다** |
| 도메인 문서 3.1 | 「방장의 삭제 권한」 이 댓글 규칙 예시로 **여전히 적혀 있다** |
| SPEC-S2 CM-10 | 「작성자 또는 방장」 |
| SPEC-S2 3장 권한표 | 방장은 「자기 글의 타인 댓글」 삭제 가능 |
| **프론트 코드** | **작성자 본인만.** 방장 삭제가 구현되어 있지 않다 |

여기는 **코드도 명세와 다릅니다.** 셋이 전부 다릅니다.

### 제 의견

**방장에게 주는 쪽입니다.** 자기 글에 붙은 것을 못 치우면 글쓴이가
할 수 있는 게 없습니다. 정하시면 코드를 맞추겠습니다.

---

## 3. 비회원이 공개 댓글을 볼 수 있는지가 앞뒤로 다르다

### 무슨 일이 벌어지나

검색으로 모집글에 들어온 사람이 **본문은 읽는데 댓글은 못 읽는다.**
로그인하라는 말도 없이 댓글 자리가 비어 있으면 글이 잘린 것처럼
보인다.

### 어디가 어긋났나

도메인 문서 7.1 표 **안에서** 두 줄이 부딪힌다.

```
모집글 본문            | 비회원 및 회원 열람 가능
공개 루트 댓글·대댓글   | 로그인 회원 전체          ← 비회원 제외?
```

| | 내용 |
| --- | --- |
| SPEC-S2 CM-20 | 비회원도 공개 댓글 본문 열람 가능 |
| 프론트 코드 | 비회원도 본다 (`comment-perm.ts`) |

### 제 의견

**「비회원 포함 전원」 이 맞습니다.** 본문을 열어두고 댓글만 막을
이유가 없습니다. 비밀 댓글은 어차피 비회원에게 전부 자리표시자입니다.

## 4. 만남 지점의 이름이 두 개다

### 무슨 일이 벌어지나

개발자마다 다른 이름을 씁니다. API 필드가 `meetPoint` 인지
`meetingPoint` 인지 붙여봐야 압니다.

### 어디가 어긋났나

| | 이름 |
| --- | --- |
| 도메인 문서 1장 용어표 | `MeetPoint` |
| 도메인 문서 3.1 애그리게이트 | `MeetingPoint` |
| 프론트 코드 | `MeetPoint` |

지난 판의 `MeetingPlan` 을 고치면서 `MeetingPoint` 가 됐습니다.

### 제 의견

**`MeetPoint` 로 통일.** 1장 용어표가 정본이고 코드도 그렇습니다.
3.1 만 고치면 됩니다.

---

## 5. 마감시각 부등호가 성립하지 않는다

### 무슨 일이 벌어지나

모집글을 올리면 **서버 검증에서 무조건 400이 납니다.** 조건이 애초에
만족될 수 없기 때문입니다.

### 어디가 어긋났나

```
도메인 문서 I-04    deadlineAt < meetAt ≤ 행사 종료시각
                            ^^^ 이게 성립하지 않는다
```

**모집 마감 입력 칸을 없앴습니다.** 비우면 만나는 날까지였으니
기본값이 곧 정답인 칸이었습니다. 그래서 **서버가 `closesAt` 을
`meetAt` 으로 채웁니다.** 둘이 같으므로 `<` 가 거짓입니다.

| | 내용 |
| --- | --- |
| 도메인 문서 I-04 | `deadlineAt < meetAt` |
| SPEC-S2 PO-02 | `meetAt ≤ 행사 종료시각` 만 검증 |
| 프론트 | 마감 입력 칸 없음 |

### 제 의견

**`deadlineAt ≤ meetAt` 으로 고치는 쪽입니다.** 마감 입력을 되살리면
기본값이 곧 정답인 칸이 하나 더 생깁니다.

| # | 어긋난 것 | 도메인 문서 | SPEC-S2 | 코드 | 제 의견 |
| --- | --- | --- | --- | --- | --- |
| 1 | 모집글 취소 | 없음 | 있음 | 있음 | **되살린다** |
| 2 | 방장의 댓글 삭제 | 없음 | 있음 | **없음** | **넣는다** |
| 3 | 비회원의 공개 댓글 | 로그인 회원만 | 전원 | 전원 | **전원** |

**2번만 코드를 고쳐야 합니다.** 나머지 넷은 도메인 문서 쪽을 손보면
끝납니다.

## 겹치는 문서를 앞으로 어떻게 둘지

같은 사실을 두 문서에 온전히 적으면 반드시 갈라집니다. 위 다섯이
그 증거입니다. **역할을 갈랐습니다.**

| | 담는 것 | 겹치는 부분 |
| --- | --- | --- |
| **도메인 모델링 문서** | 무엇이 참인가. 용어 · 애그리게이트 · 불변식 · 상태 전이 | **정본** |
| **SPEC-S2** | 무엇을 만드나. 기능 ID · 우선순위 · 검증 기준 · 일정 | 요약 + 링크 |

`SPEC-S2` 에서 겹치던 셋을 이렇게 줄였습니다.

- **2장 용어 정의** 화면 문구와 직결되는 아홉 개만 남기고 링크
- **4장 상태 정의** 전이 규칙은 링크하고, **화면 배지**만 남김
  (배지 글자는 도메인 문서에 없는 정보라 이쪽이 정본)
- **5-4 CM-04 권한 매트릭스** **양쪽에 그대로 둠**

세 번째는 일부러 겹쳐뒀습니다. 비밀 댓글 권한은 배포 판정의 핵심이라,
명세를 보는 사람이 문서를 두 개 열어야 하면 그게 빠뜨리는 원인이
됩니다. 대신 **「어긋나면 도메인 문서가 이긴다」** 를 표 위에
적어뒀습니다.

## 닫힌 것

**Q-04 (관리자의 비밀 댓글 열람)** 은 도메인 문서 7.1 이 「관리자 열람
가능」 으로 확정했습니다. `SPEC-S2` 에서 미결 목록에서 뺐고,
**AD-05(감사 로그)를 권장에서 필수로 올렸습니다.** 열람을 허용하면
감사 로그가 유일한 견제 장치입니다.

## 아직 답이 없는 것

**API 필드 표기 (Q-17).** 도메인 문서는 `meetAt` 인데 프론트
`types.ts` 는 `meet_at` 입니다. 그 파일이 그대로 API 명세로 넘어갈
물건이라 여기서 갈리면 나중에 전부 고칩니다. **camelCase 로 가면
프론트를 맞추겠습니다.**
