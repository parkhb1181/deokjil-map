# QA 이슈 기록

1차 MVP 를 실서버에 붙인 뒤 나온 것들을 모았다. 프론트엔드 기준이고,
백엔드에 넘긴 것도 어디서 막혔는지 알 수 있게 같이 적는다.

기간은 2026-09-09 ~ 09-10. 확인한 곳은 duckmoim.com(프로덕션)과
api.duckmoim.com(실서버)이다.

- 고쳐서 배포함 · 18건
- 리뷰로 머지 전에 막음 · 1건
- 아직 막혀 있음 · 5건

## 2. 리뷰로 머지 전에 막음

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 크롤러가 새로 적재한 행사의 상세가 404 난다. 홈과 `sitemap.xml` 에는 뜨는데 눌러보면 없다 | `/e/[id]` · `/a/[subject]` 의 `dynamicParams = false`. 유효한 주소는 빌드 때 정해지고, `revalidatePath` 는 이미 만든 페이지를 다시 그릴 뿐 목록을 못 늘린다 | PR #12 리뷰에서 지적 → 작성자가 `dynamicParams` 를 켜고 깨진 인코딩용 try/catch 를 추가 (`e5c7192`) |

재현으로 확인했다. 빌드 목록을 3건으로 줄여 빌드한 뒤 목록 밖 id 를
부르면 404, `dynamicParams = false` 를 지우고 다시 빌드하면 200 이고
없는 id 는 그대로 404 였다.

## 4. 확인만 하고 넘어간 것

**행사 적재 건수** — 서버 104건 대 번들 197건이라 API 전환을 미뤄
두었는데, 백엔드가 채워서 195건이 됐다. 콘서트 14건도 다 들어와 있다.
번들과의 차이는 어제 끝난 10건과 서버에만 있는 5건이라 실질 손실이
없어서 전환했다 (`73f34c8`). 주소는 응답의 `externalId` 를 쓰므로
색인된 페이지가 안 죽는다.

**댓글 삭제** — 이미 소프트 삭제다. 서버가 행을 지우지 않고 상태만
`DELETED` 로 바꾸고, 하위 답글이 있으면 자리표시자로 남는다. 모집글
삭제를 요청할 때 이 방식을 그대로 쓰면 된다는 근거가 된다.

**재검증 라우트** — PR #12 머지 후 `POST /api/revalidate/events` 가
401 을 준다. 키가 없으면 503 이므로, 401 은 라우트도 키도 붙었다는
뜻이다. 크롤러가 실제로 돌 때 200 을 받는지만 남았다.
